BOOT — build and release
========================

Prerequisites
-------------
Linux x86-64, GNU make, GCC, binutils, GNU-EFI headers/libraries, Git.
Release packaging additionally requires dpkg-deb and sha256sum.
GNU-EFI must be capable of producing x86-64 PE32+ UEFI executables.

Local firmware compilation (no deployment)
-------------------------------------------
  make gnuefi
  file boot/boot_x64.efi

The build also produces the optional historical GPTSync executable. Its
existence is not an invitation to modify partition tables. Do not invoke
make install during automated packaging: installing BOOT requires an
intentional ESP and EFI firmware change.

  make clean

The clean target is restricted to this checkout. It must never remove
files from an external EDK2 toolchain.

Release
-------
Current CI uses version 0.1.<GitHub run number>, embeds that same version
in the compiled firmware and creates a matching SBAT record. SBAT does
not make an unsigned build Secure Boot-compatible: signing, trust and
revocation must be independently qualified.

  bash packaging/build-release.sh 0.1.123 dist
  bash packaging/test-release.sh 0.1.123 dist

The first command requires a compiled boot/boot_x64.efi and a Git HEAD.
It generates a small native .run that includes the full original
boot-install implementation but does not embed the rest of the repository.
At execution time it fetches the exact pinned commit, compiles locally,
and executes its embedded installer. The .run is not a build-only tool.

The .deb is a generic non-deploying payload. It neither mounts an ESP nor
alters firmware BootOrder. Only the native installer performs deployment.

EFI installation boundary
-------------------------
Default executable:
  /EFI/InfiltratorOS/BOOT/BOOTX64.EFI

Shared /EFI/BOOT, Microsoft Boot and GRUB EFI paths must not be modified.
The installer must refuse unfamiliar firmware executables rather than
overwrite them, preserve an existing BOOT NVRAM entry when reprioritising
it, and propagate errors. No old installations require automatic cleanup.

Filesystem modules
------------------
Common V2 is the sole target filesystem contract; independent format
repositories own their implementations. BOOT must eventually authenticate
and load the freestanding Common V2 profile through a purpose-built UEFI
loader. An ordinary hosted ELF .so cannot simply be passed to UEFI LoadImage.
This work is not yet implemented/qualified in BOOT, and historical .efi
filesystem readers are not the accepted final architecture.

Verification
------------
GitHub Actions tests build compatibility, package integrity, pinned source
metadata and selected static invariants. It does not demonstrate real ESP,
NVRAM, Secure Boot, Windows preservation, Common V2 file loading or kernel
handoff. Do not call the firmware production-validated without those tests.
